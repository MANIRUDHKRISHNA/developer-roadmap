# 🎯 Placement OS

> **Goal:** Become interview-ready fast without trying to "master
> everything" at once.\
> **Timeline:** September 11 → September 30, 2026\
> **Primary strategy:** Company preparation first, then a small daily
> baseline across DSA, SQL, projects, CS fundamentals, and interviews.\
> **Learning rule:** 20% theory → 50% building → 10% breaking → 10%
> debugging → 10% explaining.

------------------------------------------------------------------------

## 1. North Star

By the end of this placement phase, I should be able to:

-   Solve common Easy/Medium DSA problems.
-   Write practical SQL without depending on autocomplete.
-   Explain OOP, DBMS, OS and Computer Networks fundamentals.
-   Build and debug REST APIs.
-   Explain my projects deeply, including architecture, trade-offs, bugs
    and improvements.
-   Explain my AWS deployment rather than merely naming AWS services.
-   Explain LLM concepts such as embeddings, semantic search, RAG and
    tool calling.
-   Defend every important technology written on my resume.
-   Handle company-specific aptitude/coding/technical rounds.
-   Communicate my project and engineering decisions clearly.

### Definition of "ready"

  -----------------------------------------------------------------------
  Level                               Meaning
  ----------------------------------- -----------------------------------
  Familiar                            I can recognize and describe the
                                      concept.

  Working                             I can implement/use it without a
                                      tutorial.

  Interview-ready                     I can explain it, code it, debug it
                                      and answer follow-ups.

  Strong                              I can reason about trade-offs,
                                      failure cases and scaling.
  -----------------------------------------------------------------------

**Target:** Core skills should reach **Interview-ready**. Projects and
the main backend/AI stack should reach **Strong**.

## Day type rules

### 🔴 RED --- Exam/interview is very close

Use when an exam/interview is today or tomorrow.

**Priority** 1. Company-specific preparation 2. Required DSA/coding
patterns 3. Project questions 4. Quick CS/SQL revision

**Target:** 2--4 focused hours.

### 🟡 YELLOW --- Normal placement day

No immediate high-pressure round.

**Priority** 1. Company preparation 2. Project mastery 3. DSA + SQL 4.
CS fundamentals 5. Interview practice

**Target:** 4--6 focused hours.

### 🟢 GREEN --- No immediate exam/interview

Use the extra time to build depth.

**Priority** 1. Project implementation 2. DSA 3. SQL 4. Backend/AWS/AI
5. CS fundamentals 6. Interview practice

**Target:** 6--9 focused hours.

> Never force a Green-day schedule onto a Red day. The calendar does not
> care about your ambitions. Your upcoming company test does.

# 23. The Practical Learning Loop

For every new concept:

### 1. Learn --- 20%

Understand:

-   What is it?
-   Why does it exist?
-   When do I use it?
-   What problem does it solve?

### 2. Build --- 50%

Implement something tiny.

### 3. Break --- 10%

Intentionally create a failure.

### 4. Debug --- 10%

Find the cause without immediately searching for the answer.

### 5. Explain --- 10%

Explain it aloud as if an interviewer asked.

If I cannot explain it after using it, I probably memorized it instead
of learning it.
